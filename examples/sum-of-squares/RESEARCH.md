# Exact sum of squares demonstrator

Objective: compute sum(k*k for k in 0..n), with exact Python int output, for every integer n in 0..1000. Reject bool and out-of-domain input. This is a bounded mathematical workload, not synthetic evidence for a real-world data task.

## Oracle provenance and validation plan (written before scorer)
The independent oracle enumerates square numbers by consecutive odd differences: square(0)=0 and square(k)=square(k-1)+(2k-1); accumulated squares then establish each expected answer. Induction on the difference identity proves the table independently of both the multiplicative loop baseline and the polynomial alternative. Hand cases are n=0 -> 0, 1 -> 1, 2 -> 5, 3 -> 14, 10 -> 385, 1000 -> 333833500. Exhaustively check all 1001 inputs and exact output types. Validate known loop and polynomial implementations, and reject constant-zero, dropped endpoint, and floating-point implementations. Invalid inputs are also checked. The baseline is only a comparator.

## Measurement and stopping plan
Minimal workflow BUILD -> MEASURE -> CONFIRM -> DECIDE; BUILD imports a named immutable test fixture, not an agent discovery. MEASURE and CONFIRM each use separate fresh evaluator subprocesses and fixed paired timing blocks. Six paired observations per invocation, alternating order, fixed workload [0,1,10,100,500,1000] repeated 100 times, warmup once, perf_counter_ns and consumed outputs. Report per-call nanoseconds and candidate/baseline ratios. Startup excluded; Python/platform/CPU recorded. Paired blocks share one process: uncertainty is descriptive min/max only, not a population confidence interval. A bounded baseline/baseline pilot diagnoses noise before experiments; block plan is fixed prospectively, not tuned to candidate results. No statistical significance or general performance claim.

Minimum useful improvement is a demonstrator operational threshold of 5%, not a business threshold. Deterministic gate requires exhaustive correctness and all six ratios below 0.95 in both exploration and a separately scheduled six-pair confirmation; otherwise retain baseline and report inconclusive/no useful improvement. No real adaptive resampling. Confirmation is reserved for the one prespecified closed-form candidate, with no repeated holdout selection. Isolated mock scenario alone exercises an explicit maximum-two-batch inconclusive -> remeasure edge.

Budget: at most 2 real experiments, 8 evaluator subprocesses total including initialization, each <=15 seconds; at most 2 measurement invocations per candidate, 0 agent calls, 0 paid calls. Agent price/telemetry is unavailable, not estimated at zero; no agent is launched. Overall demo execution bounded by 180 seconds. Local CPU use is measured but not monetized. Initialization is setup, not discovery. No indefinite loop.

Backend is explicitly unavailable. Runtime/controller and genuine domain measurement can be demonstrated; agent integration and unrestricted scientific-ready status remain blocked. Test fixture provenance is distinct from real observations. Same-user Python execution is not an adversarial security boundary; only trusted checked-in candidates are supported.
